# NestUp analytics event dictionary

## Shared contract

All names use lowercase `snake_case`. `created_at` is generated by Supabase in
UTC. `user_id` is the authenticated Supabase account UUID or `NULL`; it is a
protected table column, never an event property. Every new app event includes:

| Property | Allowed value | Purpose |
| --- | --- | --- |
| `session_id` | Privacy-safe random ID for one app launch | Connect signed-out and signed-in steps in one launch |
| `language` | `en`, `he`, `fr`, `ru` | Compare product behavior by active app language |

The properties JSON can later add allow-listed `acquisition_source` and
`acquisition_campaign` strings without a migration. Never send search text,
message text, names, email, phone, dates of birth, address, coordinates, profile
text, tokens, or secrets.

## Funnel events

| Event | Trigger | Additional allowed properties | Product question |
| --- | --- | --- | --- |
| `app_opened` | Auth provider mounts once for an app launch | none | How many launches enter the funnel? |
| `onboarding_started` | Email or Apple profile-setup screen first mounts | `onboarding_method`: `email`/`apple` | Where does onboarding begin and which method is used? |
| `onboarding_completed` | Profile and child setup completes successfully | none | What share of onboarding sessions finish? |
| `sign_up_started` | Supabase account creation is submitted | none | How many users attempt account creation? |
| `sign_up_completed` | Account and profile setup complete | none | How many account creations succeed end to end? |
| `login_started` | Email or Apple login is invoked | `login_method`: `email`/`apple` | Which login method is attempted? |
| `login_completed` | Authenticated login succeeds | `login_method`: `email`/`apple` | Which login method converts? |
| `language_changed` | User selects a language | `language`: `en`/`he`/`fr`/`ru`/`ar`/`es` | Which languages are chosen? |
| `discovery_opened` | Discovery screen mounts | `discovery_mode`: `mixed` | How many sessions reach Discovery? |
| `discovery_search_used` | A 2+ character search is submitted | `query_length` only | Is Discovery search used without collecting its text? |
| `discovery_filter_changed` | Content/category/quick filter changes | `filter_type`, `filter_value` from fixed catalogues | Which filters help people explore? |
| `discovery_sort_changed` | List sort changes | `sort` from fixed sort catalogue | Which list ordering is useful? |
| `discovery_item_opened` | Activity, Place, or Event opens from Discovery | `content_type`, `content_id`, `discovery_mode` | Which content types convert from Discovery? |
| `activity_opened` | Activity Details mounts for an activity | `content_id`, `source`: `user` | How often are Activities viewed? |
| `activity_created` | Activity insert succeeds | `content_id`, fixed `category` | How often does creation finish? |
| `activity_joined` | Join RPC succeeds | `content_id` | Which Activity views lead to joining? |
| `activity_left` | Leave write succeeds | `content_id` | How often are joins later removed? |
| `event_opened` | Event Details mounts for an occurrence | `content_id`, provider `source` | How often are Events viewed? |
| `event_rsvp_joined` | NestUp “I’m going” upsert succeeds | occurrence `content_id` | Which Events gain social attendance? |
| `event_rsvp_left` | NestUp RSVP removal succeeds | occurrence `content_id` | How often is an Event RSVP removed? |
| `place_opened` | Place Details mounts | `content_id`, `source`: `curated` | How often are Places viewed? |
| `chats_opened` | Chats screen gains focus | none | How many sessions reach messaging/community? |
| `forum_opened` | A forum route mounts | fixed `forum_key` | Which forums are entered? |
| `forum_joined` | Forum membership is successfully ensured before chat opens | fixed `forum_key` | Which forum entries reach an authorized chat? |
| `chat_message_sent` | Activity chat message insert succeeds | internal `chat_id` | Does Activity chat entry become engagement? |
| `forum_message_sent` | Forum message insert succeeds | `forum_session`: `true` | Does forum entry become engagement? |
| `public_profile_opened` | Existing Public Profile mounts | none | Does social context lead to profile exploration? |
| `profile_updated` | Profile update succeeds | none | Do caregivers enrich their family profile? |
| `account_deleted` | Account deletion RPC succeeds | none | How often is account deletion completed? |

## Weekly Digest events

Only public Event identity/taxonomy and delivery context are allowed. Email,
push tokens, profile text, child data, birthdates, and private coordinates are
never properties.

| Event | Trigger | Allowed properties | Product question |
| --- | --- | --- | --- |
| `weekly_digest_generated` | Server produces a non-dry-run weekly selection | `week_start`, `city`, `result_count` | Is enough eligible weekly content available? |
| `weekly_push_eligible` | Server finishes the weekly preference/token eligibility query | `week_start`, `city`, `result_count` | How large is the opted-in weekly audience? |
| `weekly_push_sent` | Expo accepts a claimed weekly delivery | `week_start`, `city`, `locale`, `result_count` | How many weekly notifications were accepted? |
| `weekly_push_skipped` | Delivery is skipped before Expo | `week_start`, `city`, `locale`, fixed `reason` | Why are eligible rows not sent? |
| `weekly_push_failed` | Claimed weekly delivery fails | `week_start`, `city`, `locale` | How often does weekly delivery fail? |
| `weekly_push_opened` | User taps a valid Weekly Digest notification | `week_start`, `city`, `locale` | Does the weekly push bring users into the curated week? |
| `weekly_digest_viewed` | Weekly Digest screen loads | `week_start`, `city`, `locale` | How many users reach the weekly recommendations? |
| `weekly_digest_event_opened` | User opens an Event from the digest | `week_start`, `city`, `locale`, `day`, `occurrence_id`, `provider`, `category`, `position` | Which days and recommendations drive Event interest? |
| `weekly_digest_closed` | User closes the Weekly Digest | `week_start`, `city`, `result_count` | Do users return to Discovery after reviewing the week? |
| `weekend_digest_generated` | Server produces a non-dry-run Thursday-Saturday selection | `weekend_start`, `city`, `result_count` | Is enough strong weekend content available? |
| `weekend_push_eligible` | Server finishes Weekend preference/token eligibility | `weekend_start`, `city`, `result_count` | How large is the opted-in Weekend audience? |
| `weekend_push_sent` | Expo accepts a claimed Weekend delivery | `weekend_start`, `city`, `locale`, `result_count` | How many Weekend notifications were accepted? |
| `weekend_push_skipped` | Weekend delivery is skipped before Expo | `weekend_start`, `city`, `locale`, fixed `reason` | Why are eligible Weekend rows not sent? |
| `weekend_push_failed` | Claimed Weekend delivery fails | `weekend_start`, `city`, `locale` | How often does Weekend delivery fail? |
| `weekend_push_opened` | User taps a valid Weekend notification | `weekend_start`, `city`, `locale` | Does the push bring users into the Weekend selection? |
| `weekend_digest_viewed` | Weekend Digest screen loads | `weekend_start`, `city`, `locale` | How many users reach the Weekend recommendations? |
| `weekend_digest_event_opened` | User opens an Event from Weekend Digest | `weekend_start`, `city`, `locale`, `section`, `occurrence_id`, `provider`, `category`, `position` | Which section and recommendations drive interest? |
| `weekend_digest_closed` | User closes Weekend Digest | `weekend_start`, `city`, `result_count` | Do users return to Discovery after reviewing Weekend? |

## Sharing events

Each share action carries `content_type` (`activity`, `place`, or `event`),
`content_id`, and `share_channel` (`whatsapp` or `native`).

| Event | Trigger | Product question |
| --- | --- | --- |
| `share_started` | A share action begins | Which content and channel do users attempt? |
| `share_completed` | WhatsApp opens or the native share sheet reports shared | Which attempts complete? |
| `share_cancelled` | Native sharing is dismissed/cancelled, including guarded repeat presentation | Where do users intentionally stop? |
| `share_failed` | Requested sharing is unavailable or errors without successful fallback | Which channel paths fail? |
| `activity_shared` | An Activity share completes | Which Activity shares succeed? |
| `event_shared` | an Event share completes | Which Event shares succeed? |
| `place_shared` | A Place share completes | Which Place shares succeed? |

When WhatsApp is unavailable and native fallback succeeds, the attempt is
recorded as WhatsApp `share_started`, followed by native `share_completed` and
the matching content `*_shared` event. This distinguishes channel intent from
the channel that actually completed.

## Compatibility events

`screen_viewed`/`user_identified` remain supported by the vendor-neutral API.
`activity_viewed` and legacy signup/chat events may exist in historical rows;
new product funnel queries should use the canonical events above.
